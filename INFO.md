## 9. Papan Warta Jemaat 📋

### 9.1 Logika Tampilan (komponen `AnnouncementBoard.tsx` & `/info`)
- **Akan Datang** (`eventDate >= hari ini`) → tampil di landing & `/info` dengan **MiniCountdown** ke hari H
- **Sudah Berlalu** (`eventDate < hari ini`) → disembunyikan dari landing publik; tetap tersimpan di database untuk arsip admin (tab "Sudah Berlalu")

### 9.2 Kategori Warta
| Kategori | Komunitas |
|---|---|
| `general` | Ibadah Raya / Umum |
| `youth` | Grow Generation Youth |
| `kidz` | COC Kidz (Sekolah Minggu) |
| `hana` | Wanita HANA & Komsel |

### 9.3 Field Warta
- `title` (judul)
- `content` (isi / deskripsi)
- `eventDate` (tanggal kegiatan — ISO date `YYYY-MM-DD`)
- `endDate` (tanggal selesai, opsional)
- `isPinned` (sematkan ke paling atas)
- `isPublished` (tayangkan atau draft)
- `badgeText` (label badge, mis. "Penting / Khusus")
- `author` (penulis / unit pelayanan)

### 9.4 Sumber Data
Warta jemaat **diinput oleh admin melalui Portal Admin** (`/admin` → tab **Warta Jemaat**). Data disimpan di tabel `announcements` di Supabase dan ditampilkan di:
- `/` & `/home` → section `AnnouncementBoard` (5 warta upcoming)
- `/info` → section "Papan Pengumuman & Warta" (with full category filter + countdown)
- `/api/public/data?table=announcements` → endpoint publik sanitasi

### 10.3 Modul Portal Admin (`/admin`)

5 tab utama:

| Tab | Modul | Tabel Supabase |
|---|---|---|
| 🔔 Warta Jemaat | CRUD warta + pin/unpin + filter publish/draft | `announcements` |
| 👥 Roster Pelayanan | Plotting pelayan 4 komunitas + WhatsApp broadcast + cetak A4 | `servant_rosters` |
| 🫶 Layanan Jemaat | Permohonan doa, baptisan, komsel, volunteer | `ministry_requests` |
| 🎬 CMS Khotbah & Galeri | Kelola khotbah + YouTube sync + foto Drive | `sermons`, `gallery_items` |
| 📦 Inventaris & Cek | Checklist sound system, multimedia, musik, ruangan | `inventory_items` |

### 10.4 Modul Portal Superuser (`/super`)

- List semua user (username, role, status aktif, login terakhir)
- Tambah user baru (username, password, role, nama tampilan)
- Edit role / password / aktif/nonaktif
- Soft-delete untuk audit trail (tidak hard delete)
- Quick-link ke `/admin` & `/kas`

### 10.5 Modul Portal Kas (`/kas`)

- **Saldo realtime**: 3 card (Total Pemasukan, Total Pengeluaran, Saldo)
- **Buku Kas**: list transaksi dengan filter tipe (income/expense) + search
- **Tambah**: tombol "Catat Pemasukan" (hijau) / "Catat Pengeluaran" (merah)
- **Kategori saran**: `iuran_anggota`, `sumbangan`, `konsumsi`, `transportasi`, `alat`, `acara`, `lainnya`
- **Validasi**: amount > 0, ≤ Rp 1 milyar, transaction_date valid
- Tabel: `youth_treasury_transactions` (dengan kolom `created_by` → `users`)
- View: `youth_treasury_balance` (aggregate income/expense/balance)

### 10.6 Endpoint Backend

| Endpoint | Auth | Fungsi |
|---|---|---|
| `POST /api/auth/login` | public | Login username+password (bcrypt) → cookie `gia_session` |
| `DELETE /api/auth/login` | session | Clear cookie (logout) |
| `GET /api/auth/check` | session | Return `{ authenticated, user }` |
| `GET /api/users` | super | List semua user |
| `POST /api/users` | super | Create user baru (bcrypt-hash) |
| `PATCH /api/users/[id]` | super | Update role/password/active |
| `DELETE /api/users/[id]` | super | Soft-deactivate (set active=false) |
| `GET /api/admin/data?table=…` | super,admin | Read CRUD table (admin/super only) |
| `POST /api/admin/data` | super,admin | Upsert rows |
| `DELETE /api/admin/data?table=…&id=…` | super,admin | Hard-delete row |
| `GET /api/public/data?table=…` | public | Read publik (filtered, sanitized) |
| `POST /api/public/ministry-requests` | public + rate limit | Submit permohonan jemaat |
| `POST /api/gallery/upload` | public (multipart) | Upload foto ke Drive + Supabase |
| `POST /api/gallery/sync` | session atau `x-sync-secret` | Sinkronisasi Drive → DB |
| `GET /api/youtube/latest` | public | Fetch video khotbah terbaru YouTube Data API v3 |
| `GET /api/youth-treasury` | super,treasurer | List transaksi + balance aggregate |
| `POST /api/youth-treasury` | super,treasurer | Create transaksi |
| `PATCH /api/youth-treasury/[id]` | super,treasurer | Update transaksi |
| `DELETE /api/youth-treasury/[id]` | super,treasurer | Hard-delete transaksi |

## 11. Environment Variables 🔐

Lihat `.env.example` untuk dokumentasi lengkap. Ringkasan:

```env
# === Supabase ===
NEXT_PUBLIC_SUPABASE_URL=https://<project-ref>.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=<anon-jwt>
SUPABASE_SERVICE_ROLE_KEY=<service-role-jwt>     # Server-only, bypass RLS
SUPABASE_ACCESS_TOKEN=<management-api-token>      # opsional, untuk sync env

# === Admin / Auth ===
# Catatan: sejak refactor multi-role (Phase 3+), password login pakai
# tabel users dengan bcrypt. ADMIN_PASSWORD masih dipakai untuk legacy
# fallback jika tabel users belum ter-seed. Tidak wajib di-set di
# production kalau akun sudah ada di DB.
NEXT_PUBLIC_ADMIN_PASSWORD=1515                   # legacy fallback
ADMIN_SESSION_SECRET=<random-32-char-string>     # HMAC key untuk session cookie

# === Google Drive (OAuth) ===
GOOGLE_OAUTH_CLIENT_ID=
GOOGLE_OAUTH_CLIENT_SECRET=
GOOGLE_OAUTH_REFRESH_TOKEN=
GOOGLE_DRIVE_UPLOAD_FOLDER_ID=
GOOGLE_DRIVE_PUBLIC_FOLDER_ID=

# === YouTube Data API v3 ===
YOUTUBE_API_KEY=
YOUTUBE_CHANNEL_ID=
```

## 12. Catatan & Prinsip Pemeliharaan 🛠️

1. **Setiap perubahan informasi** di file ini (mis. nomor rekening baru, tambahan nama struktural, pergantian jadwal) → harus diupdate juga di data production melalui **Portal Admin** atau via migration SQL.
2. **Jangan hardcode nomor rekening / data sensitif** di komponen publik — gunakan env var atau field DB.
3. **Password default** di file ini (`1515`, `5050`, `1234`) hanya untuk setup awal. Production harus langsung diganti melalui `/super` setelah login pertama.
4. **Link Zoom ibadah do'a pagi** masih sementara dan akan diperbarui — update via komponen `ScheduleSection.tsx` setelah link baru tersedia.
5. **Struktur multi-portal**: `/` redirect ke `/home`, lalu navigasi internal via Navbar. Portal admin/super/kas adalah route terpisah yang masing-masing memerlukan login.
6. **RBAC**: helper `requireRole(req, ['super', 'admin'])` di API routes memastikan role enforcement. Jangan bypass di route baru.
7. **Akun user baru** dibuat via `/super` → bcrypt cost 10, disimpan di tabel `users`. Password tidak pernah di-log atau di-display plain.
